# Backlog

This backlog is focused on Version 0 of the Rust-based agent workspace execution tool.

Version 0 should provide the smallest useful execution primitive for a coding agent:

> Run one foreground command inside a controlled workspace, capture the result, return structured JSON, and record basic execution evidence.

The project is still documentation-first. Implementation work should begin only after the v0 contract is stable enough to guide a coding-agent session without requiring architectural invention.

## Version 0 Goal

Enable a coding agent, human developer, or script to call the tool with a command such as:

```bash
llm-shell run --cwd ./repo --timeout 30 -- cargo test
```

The tool should eventually:

- parse the request;
- validate the request shape;
- run one foreground command;
- apply the selected working directory;
- enforce a timeout;
- capture stdout and stderr separately;
- report exit code and duration;
- return structured JSON;
- produce a basic machine-readable execution log.

Version 0 is not the full agent workspace tool. It is the first execution primitive required for that tool.

Later versions may add workspace inspection, process sessions, validation workflows, policy profiles, and agent-facing adapters. However, v0 should remain focused on proving the controlled command execution path.

## Version 0 Design Decisions To Close

Before implementation begins, decide the following:

1. Whether `--cwd` is required or defaults to the current directory.
2. Whether timeout is required or has a safe default.
3. What the default timeout should be if one is allowed.
4. Whether the command must always appear after the `--` separator.
5. Whether the internal command model is always an argument vector.
6. Whether shell-string execution is excluded from v0.
7. Whether environment variables are inherited by default.
8. Whether the v0 log includes stdout and stderr or only metadata.
9. Where basic execution logs are written.
10. Whether request IDs are generated by the CLI, broker, or caller.
11. How timeout should be represented in the response.
12. How startup failures should differ from non-zero command exits.
13. Whether v0 timeout only terminates the direct child process or attempts to terminate the process group.
14. Whether v0 supports direct executable invocation only or allows shell-mediated execution.

  - [ ] The CLI accepts `run --cwd <PATH> --timeout <SECONDS> -- <COMMAND> [ARGS...]`.
  - [ ] The CLI rejects missing command payloads.

  - [ ] The CLI converts valid input into a typed v0 request structure.

  - The command should parse into a typed request.
  - It should not execute `cargo test` yet.

  - What changed:
  - Why this approach:
  - Evidence:

The third implementation task should add timeout behavior.

## Version 0 Task Sequence

### Phase 0: Documentation Contract

- Align `README.md`, `AGENTS.md`, and docs around the workspace-tool framing.
- Finalize `CLI_CONTRACT.md`.
- Finalize `REQUEST_RESPONSE_SCHEMA.md`.
- Finalize `SECURITY_MODEL.md`.
- Finalize `PRODUCT_SPEC.md`.
- Finalize `ARCHITECTURE.md`.
- Record decisions in `DECISIONS.md`.

### Phase 1: CLI Request Parsing

- Create Rust crate.
- Add CLI parser.
- Parse `run`.
- Parse `--cwd`.
- Parse `--timeout`.
- Parse command payload after `--`.
- Convert input into a typed request.
- Do not execute commands yet.

### Phase 2: Foreground Command Execution

- Execute one foreground command.
- Apply working directory.
- Capture stdout.
- Capture stderr.
- Capture exit code.
- Capture duration.
- Return structured JSON.

### Phase 3: Timeout Handling

- Enforce timeout.
- Return `timed_out` status.
- Represent missing exit code correctly.
- Document timeout behavior.

### Phase 4: Basic Logging

- Add one machine-readable log record per execution.
- Log request ID, command metadata, cwd, status, exit code, duration, and timestamp.
- Avoid logging secrets beyond what the explicit command already exposes.
- Keep logs separate from user-facing JSON output.

## Deferred Until After Version 0

The following are intentionally out of scope for v0:

- long-lived sessions;
- background processes;
- process groups beyond what is required for timeout behavior;
- streaming output;
- interactive terminal UI;
- command allowlists or denylists beyond basic request validation;
- advanced approval workflows;
- MCP integration;
- JSON-RPC or HTTP server mode;
- patch application;
- repository diff analysis;
- autonomous planning;
- code editing;
- cross-machine execution.
